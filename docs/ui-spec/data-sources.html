2. 観測点のリアルタイム震度: 強震モニタ 要確認が多い

  • 提供物: 全国の強震観測網のリアルタイムの揺れ (震度・加速度) を表示するサービス。公式の説明ページは https://www.kyoshin.bosai.go.jp/kyoshin/docs/new_kyoshinmonitor.html と案内されているが、今回は HTTP 503 で取得できず (トップページと docs の目次も 503)。
  • JSON の WebAPI があるか・エンドポイント・画像タイルの形式・更新頻度: 公式ページから確認できず。前回の回答で「JSON の WebAPI として提供」と書いたのは、気象庁の検討会資料の検索結果の要約に基づくもので、公式の仕様ページでの確認は取れていません。
  • 利用規約・二次利用・YouTube 配信・サーバ側での定期取得・負荷の目安・クレジットの条件: 確認できず。
  • 参考 (強震モニタ本体の規約ではない): 検索結果の要約に、K-NET・KiK-net のデータについて「利用者を不特定として制限なく使用できる」「謝辞等に防災科研の K-NET・KiK-net の情報を利用したことを明示」とあった。原文は未確認で、強震モニタにそのまま当てはまるかも不明。
  • 参考: JQuake (デスクトップソフト) は、強震モニタの観測点データを表示する (検索結果の要約。JQuake の公式ページ https://www.jquake.net/en/about.html は未取得で、確認は要)。
次にやること (要・人の判断): ① 公式の docs ページが復旧したら取り直す。② 規約が読めない場合は、防災科研へ問い合わせる (二次利用・YouTube 配信・サーバ経由の再配信の可否)。③ 負荷の目安 (取得間隔)。

3. 台風情報: 気象庁 防災情報 XML 中

  • 提供物: 台風解析・予報情報 (VPTW60〜65 など。5 日予報を含む)、台風に関する情報 (VPTI50〜52)。
  • 入手方法: PULL 型の XML 配信で、登録は不要 (https://www.data.jma.go.jp/developer/index.html で確認)。うちがすでに気象警報で使っている仕組みと同じ。
  • JSON での配信、更新頻度、具体的なフィードの URL: 今回の調査では確認できず (要確認)。
  • 利用条件: 気象庁ホームページの利用規約に準拠 (次の 4 章)。

4. 雨雲レーダー: 高解像度降水ナウキャスト 中

  • 提供物: 250m 格子、30 分先まで (35〜60 分先は 1km)、5 分ごとの更新。GRIB2 (gzip) での提供 (検索結果の要約。出典の資料の原文は未確認で、要確認)。
  • タイル配信: 気象庁サイトのタイルのエンドポイントと、タイルの利用に関する個別の規定は、今回取得したページでは確認できず (要確認)。https://www.jma.go.jp/bosai/nowc/ は画像の参照のみで API の情報なし。/developer/gpv_tile.html は 404。

気象庁のコンテンツの利用条件 (取得できた規約)

出典: https://www.jma.go.jp/jma/kishou/info/coment.html

  • 「公共データ利用規約 (第 1.0 版)」に準拠する。個別の法令により利用に制約がある場合がある、とも明記。
  • 出典は必須。例:「出典：気象庁ホームページ（当該ページの URL）」。
  • 加工した場合は、編集・加工を行ったことを記載する。加工した情報を、あたかも国が作成したかのような態様で公表・利用してはいけない。
  • リンクフリー。情報を用いて行う一切の行為について、気象庁は責任を負わない。

自動収集についての文言 (注意)

出典: https://www.data.jma.go.jp/niigata/menu/policy.html (新潟地方気象台の同旨の規定。本庁ページの原文は未確認)

「自動巡回ソフト等による、定期的、自動的な気象データの収集等は、サーバーに負荷がかかる等の理由から、原則としてご遠慮いただいております」

サーバが定期的に取りに行く運用は、この文言に当たりうる。うちは気象警報 (防災情報 XML、5 分ごと) と天気 (アメダス 10 分ごと・天気予報 1 時間ごと、jma.go.jp/bosai の JSON) を定期取得している。「ご遠慮」の文言がより直接当たるのは、防災情報 XML ではなく bosai の JSON (天気) 側。既存の取得も含めて、取得間隔を長めに・キャッシュして配信側に一本化する運用が無難。気象庁の「防災情報 XML」のように、公式に自動取得が想定されている入口を使うのが望ましい。

5. すでに使っているデータ源の条件 中

P2P地震情報

  • 開発者向けのページ (https://www.p2pquake.net/develop/、/develop/json_api_v2/) には、利用規約・再配布・クレジット・アクセス頻度の記述が見当たらない (/terms/ は 404)。
  • 確認できたのは「緊急地震速報 (警報) を含む全情報が利用可能な API です。WebSocket API は、低遅延で受信可能です。」という説明のみ。
  • EPSP の仕様のリポジトリ (github.com/p2pquake/epsp-specifications) は MIT ライセンスだが、これはプロトコル仕様のライセンスで、配信されるデータの再配布条件ではない。
  • 再配布の条件は未確認。運営者へ確認するのが確実。

Wolfx Open API

出典: https://wolfx.jp/en/legal/terms

  • 個別のドキュメントまたは元データの規約が許さない再提供・再販売・再利用は禁止 (原文: "re-provide, resell, or otherwise reuse data in a manner not permitted by the Service-Specific Documentation or applicable data-source terms")。
  • レート制限・接続数の制限をプロジェクトが設けうる。回避は禁止。
  • 気象庁など元データの権利は各権利者に帰属。公式の警報として提示すること・公式や提供元へのなりすましは禁止。
  • API のドキュメントには「reference only」の免責がある。
