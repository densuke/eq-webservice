# 平時の天気の札に「明日の天気」を交互に出す (v0.20.x)

2026-10-01 の利用者の案。
平時の地図の主要都市の天気の札で、「今の天気と気温」と「明日の天気・最高/最低気温・降水確率」を一定の間隔で交互に出す。
web (eq.fuga.jp) と YouTube の配信 (native) の両方でそろえる。

## 1. 今の作り

- サーバ: `crates/eq-server/src/city_weather.rs`
  - 13 都市の今の天気は、気象庁の予報の JSON (`/bosai/forecast/data/forecast/{office}.json`) の今日の天気と、アメダスの気温・雨を組み合わせる。
  - `parse_forecast`・`summarize`・`FORECAST_EVERY`。
  - `GET /api/weather` で返す (`CityWeather`)。
- web: `web/src/weather.ts`・`weather-layer.ts` (`renderCityWeather`)、`main.ts`。
- native: `crates/eq-server/src/broadcast/native/data.rs` (`CityWeather`)、`calm.rs` (札の描画)、`icon.rs` (天気のアイコン)。

## 2. 足すもの

1. **サーバ**: 予報の JSON から、各都市の「明日」の次の値を取り、`/api/weather` に足す。
   - 天気のコードと文。
   - 最高・最低気温。
   - 降水確率。明日の 6 時間ごとの値の最大か、並びのまま返すかは担当が決めて、理由を書く。
   - 予報の JSON の形 (timeSeries の並び、地域・気温の地点のコード) を実物で確かめて、どの値を使うかをコメントに残す。
   - 取れない値は無しにする。発表の時刻 (5・11・17 時) によって明日の気温が片方しか無いことがある。
   - 既存のクライアント (native・web の古い版) が壊れないように、項目は足すだけにする。
2. **表示** (web と native)
   - 平時の天気の札を、**20 秒ごと** に「今」と「明日」で切り替える。
     - 間隔は設定で変えられるようにする。web は既存の設定の仕組み (`app.settings`) があればそこに、native は broadcast.toml の項目にする。
   - 明日の札は、次のものを 1 枚に収める。
     - 天気のアイコン (今と同じ気象庁のアイコン)
     - 最高/最低気温 (例 `24°/17°`)
     - 降水確率 (例 `30%`)
   - 今か明日かがわかるように、小さく「明日」と入れる。
   - 札の大きさはできるだけ今と同じにして、ほかの札や別枠と重ならないようにする。
   - 地震の画面では今までどおり札を出さない。
   - 切り替えの瞬間にちらつかないようにする。native は 2fps なので、フェードは要らない。
   - native の描き直しは切り替えのときだけにして、平時の CPU を増やさない。
3. テスト
   - サーバ: 予報の JSON の実物の形を小さくした例から、明日の値が取れること。気温が片方しか無い場合、降水確率が無い場合。
   - web・native: 切り替えの判定 (時刻 → 今か明日か) を純粋な関数にしてテストする。

## 3. 確かめ方 (Mac)

- 本番の気象庁のデータ (取得は既存の道具・サーバの取り方で) を使って、手元の eq-server を立てる。
- web は組み込みのブラウザで、札が 20 秒ごとに切り替わることを確かめる。パソコンとスマホの幅の両方で見る。
- native は `tools/broadcast_load.py x --server <手元> --duration 60 --keep` で書き出し、PNG を 2 枚 (今と明日) 切り出す。
- 平時の CPU・メモリを前後で比べる。

## 5. 切り替えの案内を 1 か所にまとめる (v0.20.3)

v0.20.2 を見た利用者の案 (2026-10-01)。

- 各地の明日の札に「明日」と書く代わりに、画面の空いた場所に 1 か所だけ、今どちらを出しているかの案内を出す。
  - 「現在の天気」/「明日の天気」。
- 札は今の天気と同じ 1 段の大きさにできるだけ近づけて、スマホでも重なりを減らす。
- 今後ほかの表示の切り替え (例: 気温の分布、雨量など) が増えたときも、同じ案内で「何を出しているか」を示せるようにする。

直すこと (web と native をそろえる):

1. **案内**
   - 平時に天気の札を出している間だけ、案内を出す。地震の画面では出さない。
   - 文は「現在の天気」「明日の天気」。明日は日付も添える (例: 「明日 10/2 (金) の天気」)。日付の形は担当が決めて、web と native で同じにする。
   - 置き場所は担当が決める。どの札・凡例・別枠・時計・警報の帯とも重ならない場所にする。
     - 候補: 地図の左下の凡例の上、時計の上、本図の右上の海。
     - web のパソコン・スマホと、native の 1280x720 の全部で確かめる。
   - 切り替えの瞬間に、札と案内が同じコマで変わるようにする (ずれない)。
2. **明日の札を小さくする**
   - 札の「明日」の文字を消す。
   - 1 段にして、天気のアイコン、最高/最低気温、降水確率を並べる。
     - 降水確率は小さめの文字にする。
     - 幅が収まらなければ、降水確率を最高/最低の下に小さく置く 2 段でもよい。
   - v0.20.2 で足した「明日の札だけ向きを変える表」は、札が小さくなって要らなくなれば消す。重なりが残る都市だけ残す。
3. **切り替えの作り**
   - 「今どれを出しているか」の判定 (v0.20.2 の `showTomorrow`・`showing_tomorrow`) を、表示の種類の並びを順に回す形にする。
     - 例: `["now", "tomorrow"]` と間隔から、今の種類を返す。
   - 案内の文はその種類から決める。
   - ただし、今ある種類は 2 つだけなので、使われない仕組み (設定で並びを変える、など) は作らない。並びを足せば増やせる、ところまででよい。
4. テスト
   - 種類の判定 (時刻と間隔と並びから、今の種類)。
   - 案内の文 (日付を含む)。
   - native: 決まった入力で 1 コマ描き、案内の位置に文字があること。
5. 確かめ方
   - web: 組み込みのブラウザで、パソコン (1440px)・スマホ (375px) の両方で、今と明日の両方の画面を見る。
     - 重なる札の組の数を、v0.20.2 と比べて報告する。
   - native: PNG を 2 枚 (今・明日)。
   - 平時の CPU・メモリが変わらないこと。
