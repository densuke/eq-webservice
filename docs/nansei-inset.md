# 南西諸島の別枠を見やすくする (v0.20.0)

2026-09-30 のトカラ列島近海の地震 (18:46・21:28) が、web でも YouTube の配信 (native) でも見づらかった。
利用者から、JQuake のように「九州の南から与那国までの島の連なり全体が見え、小さな島も点で見える」別枠にしたいと要望があった。

## 1. 今の作り (2026-10-01 の調査)

- 範囲
  - 別枠の範囲は web・native とも東経 122.9〜131.4 度、北緯 24.0〜30.0 度で、トカラ・奄美はもう入っている。
    - web: web/src/map.ts:32 の INSETS。
    - native: crates/eq-server/src/broadcast/native/frame.rs:21-28 の OKINAWA。
  - 本図の HOME は北緯 30 度で切れていて、トカラは本図の外。
- 見づらい原因は **縮尺**。
  - 枠の高さ 150px で 6 度を映すので、1 度 25px。トカラの島は 1px 未満の点になる。
  - トカラは枠の上の端 25px に詰まっている。
- web の地震の出方
  - トカラの地震は、本図の下の端の画面外の矢印 (map.ts:562-577) と、別枠の小さな ✕ に分かれて出る。
  - web の別枠には P 波・S 波が出ない (waveLayer は base の外、map.ts:178)。native の別枠には出る。
  - web には、枠のすぐ外の震央を縁に寄せる処理が無い。native には R3.1 の `marker` がある。
- 地図のデータ (tools/simplify_geojson.py: TOLERANCE 0.008 度・MIN_AREA 0.0004 度²) で、小さな島が消えている。
  - トカラの臥蛇島・平島・小宝島・横当島。
  - 硫黄鳥島、沖大東島、鳩間・池間・来間・水納。
  - 渡名喜は japan.geojson だけに無い。
  - 尖閣は元データ (地球地図日本) に無い。
- MIN_AREA を下げるだけでは残らない。約 1km² の輪は DP で点が 3 つ以下に潰れ、`len(dedup) < 4` で捨てられる (simplify_geojson.py:55-64)。

## 2. 決めたこと (2026-10-01、利用者の了承済み)

1. **範囲**
   - 別枠を東経 122.5〜131.5 度、北緯 24.0〜31.0 度にする。大隅諸島・九州の南の端・大東諸島 (北・南) まで入れる。
   - web と native で同じ範囲にする。
2. **大きさ**
   - native は高さ 150px → **220px** (幅は縦横比から)。左上の置き場所 (x 10、y バーの下 +10) は今のまま。
     - 250px 以上は、沿海州の深発地震の震央を枠が隠すので取らない。
   - web のパソコン向けも同じ比率で大きくする (150 → 220px)。スマホ向けは 100 → 140px 程度。
     - 枠の高さを前提にした値を直す: カウントダウンの top、スマホの凡例の top、高さの低い画面の凡例の規則 (web/public/style.css:120・234・269-275・291・293)。
     - 高さの低い画面では、枠と凡例が重ならないようにする。
3. **小さな島**
   - 南西諸島の四角 (北緯 31.5 度より南かつ東経 132 度より西) の輪だけ、残す基準を緩める。
     - MIN_AREA を 0.00008 度² (約 0.9km²) にする。
     - DP で 4 点に満たなくなる小さな輪は、TOLERANCE/4 で残すか、最低限の形 (小さな四角や菱形) で残す。jma_warning_areas.py:33-35 と同じ考え方。
   - 全国では緩めない。
   - 同じ基準を japan.geojson・areas.geojson・warning-areas.geojson の 3 つに入れて、作り直す。
     - 道具: tools/simplify_geojson.py・jma_areas.py・jma_warning_areas.py。
     - 元データは各道具が取ってくる公開データを使う。
   - 大きさの目安: 各ファイルが +5〜10KB 程度。大きく増えたら報告する。
4. **web の別枠にも P 波・S 波を描く** (native とそろえる)。
   - web にも、枠のすぐ外の震央を縁に寄せる処理を入れる。規則は native の frame.rs の `marker`: 範囲を 1.5 度広げた中の震央を、枠の縁から 8px の内側に寄せる。
5. 元データに無い島 (尖閣・沖大東島) を別のデータから足すことは **しない**。
6. native の小笠原の別枠は今回は作らない (別の宿題)。

## 4. 確かめ方 (Mac)

- 作り直した geojson で、1 章の消えていた島 (臥蛇島・平島・小宝島・横当島・硫黄鳥島・鳩間・池間・来間・水納・渡名喜) が残ったかを、輪の重心で確かめる。
  - 各ファイルの大きさの前後を書く。
- web
  - 組み込みのブラウザで全体図を開き、次の 3 つを確かめる。
    - 別枠が大きくなり、トカラの島が見えること。
    - 凡例・カウントダウンと重ならないこと。
    - スマホの幅 (resize_window の mobile) でも崩れないこと。
  - 2026-09-30 21:28 のトカラ列島近海の地震 (本番の `https://eq.fuga.jp/api/archive?from=1790771000000&to=1790772500000` の範囲を目安。読むだけ) を再生して、別枠に ✕ と地震波が出ること。
- native
  - `tools/broadcast_load.py` で平時と noto2024 を書き出す。
  - PNG で別枠を確かめる (トカラの島、那覇の天気の札、枠が日本海の陸や凡例にかからないこと)。
  - 平時と地震の CPU・メモリを、変える前と比べる。
- **重い試験 (ビルド・描画) は、別の担当の 2 時間の連続試験 (~/tmp/r22) が終わってから行う。** `pgrep -fl "tmp/r22"` で確かめてから始める。
