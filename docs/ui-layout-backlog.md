# 画面のレイアウト: 今後の課題

画面を「部品」と「レイアウトの定義」で組み立てる取り組み (docs/ui-spec/) の、残っている課題の一覧。
済んだこと・決まったことは docs/ui-spec/layout-system.html の第 6 章、現状の分析は docs/ui-spec/index.html。

## 済んだこと

- 第 1 段階: いまの web の並びを、レイアウトの定義 (web/src/layout.ts) から組み立てる形にした。見た目は変えていない (v0.31.2)。
- 横向きのスマホ (幅 801px 以上・高さ 480px 以下): 帯を地図の上の札にし、EEW は 1 件ずつ巡回する (v0.32.0)。
- 段階 0.5: レイアウトの定義を外のファイル (JSON) に出した。組み込みは `web/src/layout.json`、eq-server の `[layout] file` で差し替え、`GET /api/layout` で配る。
  ファイルを書き換えてブラウザを再読み込みすれば変わる (ビルド・再起動は要らない)。正しくなければ web が組み込みの定義を使う (v0.33.0)。
  部品そのもの (web の app.js・Rust の native) はこれまでどおりビルドに入れる。Rust の動的ライブラリ (.so) の部品は、ABI が安定しないので採らない。
- 部品の省略: 定義は部品を高々 1 回置く (必須は main だけ)。省いた部品と使わない容器は、body 直下の隠し置き場へ移す。
- 積みの余白と場所取り: 重ね物の積みに gap・pad・minHeight を書けるようにし、スマホ縦の CSS の補い (時計は角から 6px など) を定義 (compact) へ移した。
- ?layout=名前 と manual: manual の定義は URL の ?layout= でだけ選ばれる試験用の定義にできる。
- 緊急地震速報の常設パネル: 発表中は最優先の 1 件、平時は最後の発表を出す。試験定義 trial (?layout=trial) だけに置いた。
- 段 A: trial を JDQ の形に並べた (左: 全国の地図 + 下の帯に時計とお知らせ、帯の札は地図の左上 / 右: 詳細・EEW パネル・履歴・出典)。
- 段 B: trial の右上にサブの地図 (最近の地震) を置いた。保持時間は layout.json の `subMap` (hold・unknownSec・fadedAlpha・fadeSec) で決める。
- 段 B の続き: サブの地図に見出しの札 (左上)・凡例 (右下、出ている震度の段階・予想・震央・P 波 S 波)・P 波 S 波の円を重ね、保持時間のあとは薄くしてからフェードアウトして消える。札と凡例は部品ではなく `#map-sub` の中の要素 (部品は高々 1 回しか置けないため)。出典はサブの地図に出さない (ページ下の出典で足りる)。
- スマホで、トースト・音の案内が時計に重なりうる問題は v0.36.3 で直した。

## 次の段階 (JDQ 型の画面へ。順に)

1. (済: 段 A。手動で選ぶ試験定義 `trial` として) JDQ の形の並び (地図は 1 つのまま)。枠と題の付いたペインの見た目は残り。
2. (済: 段 B) 2 つ目の地図 (最新の地震へ寄った図)。JapanMap に設定を足して 2 つ作れるようにし、trial の右上に置いた。
3. 下段の部品: 最近の地震の大きな札 7 枚・警報注意報のパネル・1 都市ずつ巡回する天気の札・「最近の大きな地震」の帯。
4. 配信 (Rust で描く native) が同じ定義ファイルを読む (Raspberry Pi 3 への移行の後)。
   要るもの: 定義の型を serde で持つ (web の `checkLayouts` と同じ確かめ方)、部品の名前 → native の描き方の対応、
   固定の 1280×720 で選ぶための条件 (例: `when: { target: "broadcast" }`。web は選ばない)、`fill`・`auto`・px・% の大きさを
   native の矩形の割り付けに直す処理 (svh・vw・clamp() は native には無いので、使えない値として扱うか、画面の大きさで計算する)。

## 課題 (優先順の目安)

### 1. 実機での確認

- iOS の Safari で、下のツールバーの出入りによる地図の高さ (60svh) の変化。
- 画面を回したとき (縦 ⇄ 横) の並べ直しと、高さ 480px をまたぐときのちらつき。
- 横向きの EEW の札の巡回の間隔 (4 秒) が読みやすいか。

### 2. レイアウトの定義の書式を育てる

- 比率に下限・上限を付けた大きさ (例: 右パネル = clamp(300px, 29%, 420px)) を使う。いまは PC の右パネルが 380px 固定。見た目が変わるので、どの画面幅で何を優先するかを決めてから。
- 状態による出し入れ (例: 平時だけ出す) を定義に書けるようにする。いまは各部品の描画の中に条件が散っている (docs/ui-spec/index.html 第 6 章)。
- 重ね物どうしの重なりの検査 (いまはプレビューの警告だけ) を、テストや実測の比較に入れる。

### 3. 縦画面 (スマホ) の改善 (要望)

- 地図を画面に固定し、下の情報の部分だけをスクロールさせる。
- スクロールすると地図を一時的に小さくし、情報の部分を縦に広く使う。
- 地図の大きさが変わるたびに、地図のカメラと天気の札の置き直しが走るので、負荷を確かめる。

### 4. 役割の部品と、参照画面のような表示 (第 2 段階)

- 状態枠 (状態文 / EEW の札 / 津波の札を同じ枠で入れ替える) を、横向き以外にも使う。
- 部品の「見せ方の段階」(簡易 / 詳細) を、津波 (JQuake 型の札 + 沿岸の色 / JDQ 型の到達予想の表) や気象警報にも広げる。
- 配信 (Rust で描く native) と、レイアウトの定義を共有する (決定。上の「次の段階」の 4)。サブの地図の分は、保持時間の表 (`subMap`) と currentGroup の選び方を model.rs に写す。
- trial を公開するときは data/banner に「JDQ・JQuake の画面構成を参考に試験中 (各ソフトの公式・提携ではない)」の告知を置く。置く前に利用者に確認する。

### 5. データ源 (docs/ui-spec/data-sources.html)

- 防災科研の強震モニタ (観測点のリアルタイムの揺れ): 利用条件から、**使わないことに決めた** (JDQ の観測点の揺れの表示は取り込まない)。
- P2P地震情報の再配布の条件を、運営者に確かめる。
- 気象庁のサイトの自動取得の方針 (「自動巡回ソフト等による定期的な収集は原則ご遠慮」の文言) と、いまの天気の取得間隔 (アメダス 10 分・予報 1 時間) を見直す。
- 台風情報 (防災情報 XML) の具体的なフィードと更新頻度。

### 6. 参照画面の未確認の場面

- JDQ: 津波の沿岸の色づけ・注意報だけの時間帯・解除、EEW が複数同時のとき。
- JQuake・JDQ: 気象警報のパネルの別の場面、離島・遠地の地震、接続が切れたときの見せ方。

### 7. 検証の環境

- 外 (スマホ) から見られる検証環境: e2 の VM が空いたので、リバースプロキシを設定すれば使える。
