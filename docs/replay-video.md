# 地震の再現動画 (R3)

地震のあと、記録 (jsonl) から当時の画面を描き直して動画にし、YouTube へ自動でアップロードする。
docs/quake-archive.md の 4 章 (R3) の続き。

## 1. 方針 (2026-09-30 決定、案 B)

- 描画は **native** (eq-server の中の Rust の描画) を使う。e2 では Chrome を使わない (メモリが足りない)。
- native に、地震波・緊急地震速報・のちに判明する震源・予想震度の札を足す。これで **ライブの YouTube 配信も同じ表示になる**。
- 再現動画は e2 の上で、記録から **nice 19 で、空き時間に** 描き直す。急がないので、リアルタイムでなくてよい。
- 音は eq-server の音の合成 (mixer) で入れる。揺れの始まりの音・2 秒ごとの刻み・警戒音 (web の R1.3 と同じ規則)。
- アップロードはキューにして、1 日に上げられる本数の範囲で順に上げる。
  - 近い震源で続いた地震は「連続地震」として 1 本にまとめ、チャプターを付ける。

## 2. 段階

| 段階 | 中身 | 確かめ方 |
|---|---|---|
| R3.1 | native に緊急地震速報と地震波を描く (ライブ配信で使う) | 記録の再生 (replay) で、手元のファイルに書き出して見る |
| R3.2 | 記録から描き直してファイルに書き出す (時計を記録の時刻で進める、音を入れる) | 茨城・与那国・能登で動画を作る |
| R3.3 | アップロードのキュー (連続地震のまとめ、チャプター、割り当て) | 非公開でのアップロードを 1 本 |

段階ごとに仕様を足し、リリースしてから次へ進む。

## 3. R3.1: native に緊急地震速報と地震波を描く

### 3.1 今の native

- 表示の判断は `crates/eq-server/src/broadcast/native/model.rs` にある (純粋な関数)。
  - web の priority.ts・groups.ts・scale.ts と同じ結果になるように作られている。
- 対象は地震情報 (Quake) だけ。緊急地震速報 (Eew) と地震波は描かない (docs/broadcast-native.md の「作らない」)。
- 地震の画面か平時かは `calm` (watch) で配信に伝わる。地震の画面では fps (10) で、平時は fps_calm (2) で描く。

### 3.2 足すもの (web と同じ見た目・同じ規則にそろえる)

web の該当する実装を読んで、同じ規則にする。web/src/waves.ts、quakes.ts (`waveSources`)、view.ts (緊急地震速報のバナー、予測の塗り)、detail.ts (`forecastTag`)、scene.ts、map.ts、alert.ts を見る。

1. **緊急地震速報**
   - 受けた緊急地震速報 (予報・警報) を、同じ地震 (event_id) の最新の報でまとめる。取り消し (`cancelled`) は消す。
   - 地震の画面にする (`calm` を false)。
     - 表示を続ける時間は web の `activeEews` と同じ規則にする。
     - 同じ地震の地震情報が届いたら、表示を地震情報に切り替える規則も web と同じにする。
   - 描くもの
     - 震源の ✕。
     - 地域・県の予測の塗り (破線または半透明。web の見た目に近いもので、native で描けるもの)。
     - 地域の予測が空のときは、✕ の近くに「予測最大震度N」の札。
     - 画面の見出し (パネル) に、緊急地震速報であることと予報か警報か、震源、予測最大震度。
       - 警報は目立つ色にする (web のバナーと同じ考え方)。
2. **地震波**
   - 起点は web の `waveSources` と同じにする。緊急地震速報があればその秒単位の発生時刻。無ければ地震情報の分単位の発生時刻。
   - 地表での P 波・S 波の半径は waves.ts と同じ式と速さ (VP 6.5km/s・VS 3.75km/s、深さを考える)。
   - 発生から `WAVE_MAX_SEC` (180 秒) で消す。
   - 同じ地震の緊急地震速報と地震情報で、波を二重に描かない。
   - 地図の投影 (native の geo.rs) で円を描く。
     - 半径は km から画面の座標に直す。緯度による歪みは、今の投影に合わせて扱う。
     - 楕円や多角形の近似でよい。
   - 波の間は、コマごとに描き直す (地震の画面の fps)。
3. **表示の判断を model.rs 側に置く** (純粋な関数、時刻は引数)。描く側 (draw.rs・panel.rs など) は判断しない。
4. 音は R3.2 で扱う。R3.1 では、今の音の知らせ (`notices`) の振る舞いを変えない。

### 3.3 やらないこと (R3.1)

- 震度の「のちに判明する震源」(再生だけの表示)。R3.2 で、記録から描き直すときに足す。
- 沖縄などの別枠の描き分けの見直し。今の native の枠の作りのまま描く。

### 3.4 テスト (cargo test)

- 緊急地震速報のまとめ: 最新の報、取り消し、表示を続ける時間、地震情報への切り替え。
- 地震波の起点の選び方と、P 波・S 波の半径 (深さあり)、180 秒で消えること。
- 予測最大震度の札を出す条件。
- 描画は、決まった入力で 1 コマ描いて、落ちないこと、画面の決まった場所の色が変わることくらいでよい。見た目の細部までは比べない。

### 3.5 確かめ方 (Mac。e2・YouTube には触らない)

- `tools/broadcast_load.py samples/scenarios/noto2024.jsonl --speed 1 --duration 150 --keep` で書き出し、ffmpeg で PNG を数枚切り出して見る。
  - 見る場面: 緊急地震速報 (警報) の直後、波が広がっている最中、地震情報に切り替わったあと。
  - `--keep` などで出力を残せないときは、手で立ててよい。
- 本番の `https://eq.fuga.jp/api/archive?from=1790744400000&to=1790745300000` (与那国、予報のみ) を、replay で読める形にして流す。形を変えるための一時的なスクリプトはコミットしない。
  - 予報の札と ✕ が出ること。
- 負荷 (`tools/broadcast_load.py`、noto2024 speed 4 の 100 秒、ffmpeg の経路、e2 と同じ encode) を、R3.1 の前と比べる。CPU とメモリが大きく増えないこと。数値を PR に書く。
